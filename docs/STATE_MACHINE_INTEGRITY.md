# State Machine & Lifecycle Integrity

BetterIlias employs a decentralized lifecycle integrity architecture to guarantee reliable, idempotent operations across multi-tenant sessions, background tasks, concurrent browser tabs, and network interruptions without relying on an all-or-nothing distributed lock.

---

## 1. Core Principles & Architecture

| Principle | How BetterIlias Enforces It |
| :--- | :--- |
| **Credential & Session Scoping** | Flight requests, caches, and event streams carry a credential generation ID; switching accounts or logging out immediately invalidates in-flight responses. |
| **Idempotent Writes & Receipts** | Destructive and creation requests carry unique `operation_id`s backed by atomic disk receipts to prevent duplicate submissions on network timeouts. |
| **Pristine vs. Dirty Editor State** | Incoming server updates never overwrite user drafts; editors reconcile fresh data only when pristine, preserving uncommitted inputs across background refreshes. |
| **Safe File Operations** | When replacing feedback files, new uploads are verified on ILIAS *before* the previous file is deleted, ensuring original student feedback is never lost on network drops. |
| **Optimistic Concurrency** | State mutations check current server fingerprints (`snapshot_token`, `distribution_fingerprint`) prior to commit, aborting cleanly if a concurrent edit occurred. |

## 2. The 14 Lifecycle Integrity Guarantees

The 14 integrity rules implemented across BetterIlias components and services:

| Rule ID | Lifecycle Area | Enforced Behavior & Safety Guarantee | Regression Coverage |
| :--- | :--- | :--- | :--- |
| **F01** | Cross-Credential Flights | Read coalescing tracks credential generation and resource ID. Stale responses from prior credentials reject upon credential change. | `test_management_flights_and_auth_events_are_credential_scoped` |
| **F02** | Calendar Concurrent Rules | Progress and import updates patch fresh tenant state under a dedicated rule/preference lock, including cancellations and failures. | Calendar interleaving test suite |
| **F03** | Grade Save vs. New Edits | Dirty state compares the live form against the submitted/confirmed snapshot. Typing during an in-flight save keeps the form marked dirty. | Deferred grade save browser tests |
| **F04** | Draft Preservation | Fresh ILIAS details initialize only pristine drafts. Active edits and pending attachments block automatic replacement. | Cached editor and deferred-response tests |
| **F05** | Feedback Replacement Safety | The replacement file is uploaded and verified on ILIAS before deleting the original file. Partial imports retain staging receipts. | Feedback upload failure & retry tests |
| **F06** | Assignment Creation Idempotency | Assignment creation requires a stable `operation_id`. Retries reconcile existing receipts rather than issuing duplicate creation POSTs. | Lost-response native markup tests |
| **F07** | Deletion Verification | File deletion is confirmed only while the new replacement file remains verified. A failed deletion reports error without marking overwrite success. | Ineffective deletion tests |
| **F08** | Stale Auth Signal Ordering | Transport events check the current credential generation; earlier-started authentication evidence cannot overwrite a newer logout or login. | Cross-account auth ordering tests |
| **F09** | Upstream Error Isolation | Upstream ILIAS HTTP 500/502/504 errors are surfaced as service unavailability rather than falsely claiming the user's session expired. | HTTP 5xx verification tests |
| **F10** | Joined Calendar Polling | An active calendar background job continues polling until a terminal status is confirmed, discarding superseded polling responses. | Joined-job observation tests |
| **F11** | Companion Session Draining | Extension companions invalidate older verification generations and drain pending cookie/forced sync requests after an attempt settles. | Deferred verification harness |
| **F12** | Modal Promise Settlement | FIFO confirmations settle each promise. Modal unmount settles abandoned requests as cancelled. Escape key handlers defer to topmost dialogs. | Queue/unmount & Escape tests |
| **F13** | Active Download Flights | URL lookups prioritize currently preparing, downloading, or saving files over historical finished entries. | Repeated download regression tests |
| **F14** | Toast & Notice Timers | Newly appended notifications reset the visual countdown; parent component re-renders do not reset timers. Hover pauses the timer cleanly. | Appended notification tests |

## 3. Receipt-Backed Operation Mechanisms

### 3.1 Creation Receipts
To prevent duplicate resource creation when an HTTP connection drops after ILIAS has already executed the POST:
- Creation requests require an `operation_id` (16–128 URL-safe characters) generated by the frontend.
- BetterIlias writes an atomic JSON receipt under `COORDINATION_DIR/assignment-creations/`, keyed by a hash of `(session_id, exercise_ref_id, operation_id)`.
- If a network error occurs, the retry request supplies the same `operation_id`. The backend checks the receipt, inspects current state, and returns the existing created item rather than creating a second copy.

### 3.2 Feedback Upload Receipts
- Each staged feedback file in mass return workflows tracks dispatch state, pre-upload file IDs, and the newly assigned replacement ID.
- Re-running or resuming a partial import verifies and reuses completed uploads without duplicating work on ILIAS.
- Staged files and receipts are pruned only after all files are confirmed or deliberately skipped, or via the 2-hour TTL staging cleanup.
